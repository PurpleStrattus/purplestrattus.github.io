Findings

  • A solution that works for all levels must be 50 or less bytes, and cannot contain any hex from: \x00\x3b\x90\x50\x73\x0f\x05.
  • Additionally, a master solution would need to survive the following loop. 
    for (int i = 0; i < 10; i++) {
        code[10 + i] = 0;
    }
    • This loop will set bytes 10-19 all equal to 0, to include 10 and 19. So, the first 10 bytes 0-9 will be safe, the next 10 byte will all be set to 0, and everything after will stay the same.
    • To survive this loop, the second set of 10 bytes must be able to be sacrificed without harming the shell code.
  • Considering the constraints, a master solution would need to not have any of the restricted byte set, have the second set of 10 bytes be sacrificial and not cause any issues if not set to 0, and the shellcode must be fully operational with only 40 bytes of shellcode.

Route to Solution

To find the solution I will need to:

  • Research lightweight reverse tcp shell capable utilities, syscalls, and methods.
  • Figure out what not being able to use \x00\x3b\x90\x50\x73\x0f\x05 actually prevents me from using.
  • Figure out alternatives to using those opcodes or ways to get around the restriction.
  • Use an AMD64 assembly reference sheet and an assembler to convert my assembly to the opcodes that our shellcode will consist of. I must check if any of the restricted opcodes somehow slipped in and adjust accordingly.

Research Results

The following are the results of my research into how I will accomplish the solution:

  • Being restricted from \x00\x3b\x90\x50\x73\x0f\x05 means:
    • x00 means I cannot use any zeros in my shellcode. This can be bypassed by using XOR to set a register to 0.
    • x3b belongs to CMP instruction in three instances:
      • CMP r16, r/m16, CMP r32, r/m32, CMP r64, r/m64
      • We will have to use different registers when using CMP and may need to use sub or xor and zero flag tests as alternatives. rely on other comparison oriented instructions more often.
    • x90 corresponds to the regular NOP instruction. This means that we cannot use any NOPs for any reason.
    • x50 means that we cannot push rax.
      • To bypass this we can just sub rsp, 8 and then mov [rsp], rax.
    • x73 restricts:
      • JAE rel8, JNB rel8, JNC rel8
    • x0f and x05 are not independent instructions in AMD64, but together, they form the syscall instruction. The filter_check() function seems to evaluate each byte independently, so any call that has x0f or x05 might trip the filter.
      • A way to bypass the syscall filter is to write instructions that modify the instruction in memory before its executed. Maybe we could add 1 to \0x0E and \0x04. This way of dynamically modifying our own code would be considered polymorphic, which coincidentally is the hint shown at level 5 in the program.
        • printf("\nYeah, you just cant use "syscall" now - cast polymorph\n>");

  • As it turns out, the 10 x00 instructions that will be set in our shellcode, actually mean something: 
    • 00 00      add    BYTE PTR [rax], al
00 00      add    BYTE PTR [rax], al
00 00      add    BYTE PTR [rax], al
00 00      add    BYTE PTR [rax], al
00 00      add    BYTE PTR [rax], al
    • This brings up a few considerations. First, I came across something that said there’s a way to edit instructions in memory or something like that. I am not sure how difficult that is or how many other instructions it’ll take, but maybe we can still use those bytes.
    • The second consideration is that the program may segfault if there is no memory address stored in rax, meaning that we may need to put a valid memory address in rax to prevent a segfault, in case we get a segfault.
    • The third consideration is that we may need to zero out rax after those operations are done. Also, the way the program sets our shellcode bytes to 0 may not do what I think it does, so it’s worth looking dynamically to see what our shellcode lookslike in memory after the zero loop runs.

  • The next thing I needed to figure out was what method of getting a reverse TCP shell would utilize the least amount of bytes.

Thoughts

  • Instead of one master solution, it may be easier to just use different shellcodes for some levels, specifically the one that sets 10 bytes to 0.
